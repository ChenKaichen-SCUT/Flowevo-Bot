## 三、实现新的 MathEvaluator-V3

不要继续采用简单增加正则表达式的方式修复问题。

请设计并实现以下模块，尽量复用成熟开源组件，例如 Hugging Face 的 Math-Verify、SymPy 和适当的 LaTeX 解析工具。

首先检查其实际支持范围、版本、依赖、许可证和已知限制，再决定如何集成。

### 模块 A：Answer Specification

根据题目确定应该提交什么类型的数学答案。

建议建立结构化 `AnswerSpec`，包含：

- 答案类型；
- 目标变量或数学对象；
- 实数、整数或其他定义域；
- 是否要求所有解；
- 是否允许多个答案；
- 集合是否无序；
- 单位要求；
- 小数精度或四舍五入要求；
- 是否为选择题；
- 是否存在题意不确定性。

支持的常见类型至少包括：

- 数值；
- 代数表达式；
- 有限集合；
- 区间；
- 不等式及其解集；
- 多项式；
- 方程解；
- 有序元组及向量；
- 矩阵；
- 带单位的物理量；
- 百分数；
- 多项选择题答案；
- 简单文本类别答案。

如果无法可靠判断题目要求的答案类型，应标记为 Unknown，不能猜测。

### 模块 B：Reference Answer Builder

这是本轮重点改进之一。

此前程序直接从标准解答中取最后一个 `\boxed{}`，导致部分多解题只保留最后一个答案。

请修改为：

**结合题目要求、原始参考解答及答案结构，构建完整的数学参考答案。**

至少支持：

- 一道题有多个 boxed 答案；
- 多个解组成集合；
- `a±b` 形式代表多个解；
- 参考答案写在连续多行中；
- 一个 boxed 包含多个答案；
- boxed 中出现中间结果，而真正最终答案位于别处；
- 答案存在多种合法表示。

不能简单地把全部 boxed 内容合并成答案，因为部分 boxed 可能是中间步骤。

必须明确记录：

- 原始参考解答；
- 找到的候选答案；
- 最终参考答案；
- 选择依据；
- 是否存在答案遗漏；
- 是否存在题意或参考答案歧义。

对于无法确定参考答案完整性的题，应标记 `reference_ambiguous` 或 `reference_invalid`，而不是强行选择某个值。

### 模块 C：Model Answer Extractor

从原始模型回答中定位其真正提交的最终答案。

支持：

- 嵌套 `\boxed{}`；
- 最后一行数学回答；
- `Therefore`, `Answer`, `Hence` 等最终结果表达；
- 不同 LaTeX 数学环境；
- 数学表达式与文字混合；
- 多个最终答案；
- 集合和区间；
- 带单位答案；
- 选择题选项。

特别需要避免：

1. 提取中间计算而不是最终答案。
2. 只提取多答案中的一个。
3. 将说明性示例误识别为正式回答。
4. 把隐藏 reasoning 中出现的候选结果当成已经交付的最终答案。
5. 将完全截断的输出当成有效最终回答。

本模块只负责提取，不负责判断答案是否正确。

不得使用 gold answer 来选择模型回答中的某个候选答案。

### 模块 D：Typed Mathematical Normalization

将不同表示方式转换为具有明确数学语义的结构。

重点支持以下此前实际发现的问题：

**1. LaTeX 包装**

例如：

`13` 与 `\text{13}`。

`odd` 与 `\text{odd}`。

`\displaystyle` 等合法排版命令不应干扰数学解析。

**2. 集合与多个解**

例如：

`{-2, 1-sqrt(5), 1+sqrt(5)}`

与：

`{1±sqrt(5), -2}`。

应正确展开 `±`，并比较集合元素，而不是字符串或错误嵌套结构。

**3. 区间与不等式**

例如：

`-4 <= k < 0`

与：

`[-4,0)`。

应比较相同变量和定义域下的解集。

**4. 数学单位**

例如：

`45 mph`

与：

`45\text{ mph}`。

支持常见长度、时间、速度、面积和质量单位。

应使用可靠的单位标准化，而不是简单删除单位字符串。

特别注意：`45 mph` 不等于 `45 km/h`。

如果题目允许不同单位，需要先进行正确的单位换算。

**5. 百分数**

结合题目要求正确处理：

`20%`、`0.2` 和作为百分数数值的 `20`。

不能无条件认为这三个字符串等价。

**6. 代数式**

支持分数、根式、多项式、代数恒等式及合法变量替换。

必须保留定义域，不得将仅在某些条件下成立的表达式无条件判为等价。

**7. 矩阵和向量**

正确解析不同的 LaTeX 包装、矩阵环境、分数系数与维度。

**8. 选择题与非数值答案**

支持 `A`、`(A)`、选项标签及一些明确的文本型答案。

不能将所有非数值结果强制送入 SymPy。

### 模块 E：Mathematical Equivalence Checker

建立类型感知的数学等价检查器。

优先使用可靠的确定性数学算法：

- 精确有理数计算；
- SymPy 符号化简；
- 多项式恒等式；
- 集合相等；
- 区间及不等式解集相等；
- 多答案集合完整性；
- 矩阵逐元素比较；
- 合法单位换算；
- 符合题目精度要求的数值比较。

对于分式约分、根式化简、对数、绝对值和不等式，要考虑定义域及数学假设。

禁止使用任意 Python `eval()` 执行答案字符串。解析与符号运算应设定超时、复杂度和资源限制。

数值抽样可以用于寻找反例或提供辅助证据，但有限次随机代入相等不能作为一般符号恒等的充分证明。

### 模块 F：分级评分与证据输出

每次评分必须返回结构化结果，例如：

```text
task_id
prediction_raw
reference_raw
answer_spec
prediction_extracted
reference_candidates
reference_complete
prediction_normalized
reference_normalized
equivalence_method
equivalence_evidence
status
reason
```

建议最终状态：

- `correct`
- `incorrect`
- `unknown`
- `reference_ambiguous`
- `reference_invalid`
- `prediction_incomplete`

特别注意：

**Unknown 不等于数学错误。**

同时，也不能因为无法解析而自动判正确。

对于 reference 本身有问题的情况，需要与模型答案错误分开。

本轮不能只生成一个独立分析脚本。

要求：

- 可通过配置选择 Legacy、Fixed、V3；

### E. 最终判断

明确回答：

**MathEvaluator-V3 是否真正比 LegacyEvaluator 和 FixedEvaluator 更可靠？**

不是只看最终正确题数，而是结合数学真实性、假阳性、假阴性和 Unknown 进行判断。

如果 V3 自动确认更多正确答案，但也引入较多假阳性，应如实判定其不够可靠。

如果 V3 更准确但仍有少量 Unknown，也应报告，不要为了消除所有 Unknown 而使用不安全的宽松匹配。

只有在数学正确性审计、回归测试和接口隔离检查均通过时，才建议将 V3 作为未来 FlowEvo 实验的默认评测器。
