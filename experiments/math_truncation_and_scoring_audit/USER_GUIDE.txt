## 二、实验一：修复 9 道数学评分假阴性

本阶段优先使用已有模型输出，原则上新增 API 调用为 0。

请逐题检查 9 道评分假阴性的完整原始输出、原评分器提取到的答案、标准答案、评分过程及错误原因。

重点检查：

- `\boxed{}` 及嵌套 LaTeX 答案提取；
- 分数、小数、根式与等价表达式；
- 多项式和代数表达式的符号等价；
- 集合、区间及多答案格式；
- 正负号、定义域、变量顺序和必要约束；
- 模型实际给出的最终答案是否被正确定位；
- 评分器是否错误提取中间计算而不是最终答案。

在现有评测器上修复通用的答案提取和数学等价判定逻辑，必要时使用 SymPy 等符号计算工具。

**禁止针对这 9 道题的 task ID 或标准答案编写特例规则。** 修复必须适用于相同类型的其他数学题。

对于无法可靠判定的数学等价关系，应标记 `unknown` 并保留人工复核证据，不能为了提高正确率而宽松判对。

修复后，必须对原始 MATH 500 道题的全部封存输出重新进行一次离线评分，而不只是检查之前答错的 9 道。这样才能发现是否还存在其他评分错误，以及新评分器是否错误地把原本正确的题判错。

生成：

- 原始评分与新评分的完整对照；
- 9 道历史假阴性的逐题分析；
- 新增纠正的假阴性数量；
- 原本正确却被新评分器改判错误的数量；
- 评分变化的数学证据；
- 对新评分器的单元测试及回归测试。

特别注意：这一步改善的是**系统的正确答案识别能力**，不代表模型新学会了解题方法。应将评分修正收益与新增模型推理收益分别报告。

## 三、实验二：27 道数学截断题的生成预算实验

这是本轮最重要的真实 API 实验。

我们需要验证：

**原本被截断的数学题，是否只需要更充足的推理和输出预算，就能够由 DeepSeek Flash 正常完成？**

首先分析 27 道题的历史响应，记录其截断发生的实际原因、已有可见解答长度、是否存在部分推理、是否已经产生最终答案，以及是否因 reasoning token 消耗导致最终答案无法输出。

### 3.1 第一组：原始基线

直接使用历史请求和响应作为基线，不需要为了重现基线而再次调用模型。

保留原始：

- 题目；
- prompt；
- 模型；
- 参数；
- 最大 token 配额；
- 实际输入与输出 tokens；
- 答案；
- 评分结果；
- 截断状态。

### 3.2 第二组：增加生成预算

对全部 27 道题重新调用 DeepSeek Flash。

除了生成预算之外，尽量保持原来的 system prompt、user prompt、temperature、输出要求和模型版本不变。

如果原实验实际最大输出预算是 4,096 tokens，且当前 API 支持，可首先将上限提高至 8,192 tokens；如原预算不同，则根据真实配置设置一个合理的更高档位。

记录每道题：

- 是否不再截断；
- 是否产生完整最终答案；
- 是否真正解对；
- 实际增加多少 tokens；
- 是否虽然输出完整，但数学答案仍错误。

数学正确性必须由独立 Evaluator 在答案提交后判定。

### 3.3 第三组：进一步增加生成预算

对于第二组仍然截断、没有形成完整答案的题目，再尝试更高的生成预算，例如在接口支持时提高至 16,384 tokens。

本组继续保持模型与基础 prompt 不变。

**是否进入第三组只能依据截断或答案完整性等在线可观察状态，不能依据离线 gold 判定是否正确。**

如果第二组已经形成完整答案，即使离线判错，也不要将其混入本组，然后把额外尝试的结果解释成单纯增加生成预算的收益。

若 API 不支持更高预算，应如实记录限制，不得静默更换模型。

### 3.4 记录真正的失败原因

实验结束后，将这 27 道题分为：

1. 增加预算后正确完成；
2. 增加预算后完成，但数学答案错误；
3. 增加预算后仍然截断；
4. 输出完整，但答案格式或解析失败；
5. 发生模型接口或环境错误；
6. 无法可靠判定。

对于第二类，进一步检查是否能够识别实际数学推导错误。

对于第三类，检查模型是否持续消耗大量 reasoning tokens 而无法输出最终答案。

不能仅凭截断判断模型不会解，也不能因为提高预算后仍然没有解出就认定模型绝对不具备解题能力。

### 3.5 不要混淆不同机制

本轮主实验只研究**更充足的生成预算是否能够恢复正确答案**。

不允许在这三组之间同时改变解题提示、注入 Skill、加入反思或改变数学方法。

如果发现更高预算仍然使部分题目无法形成最终答案，可以提出下一轮探索“推理过程压缩”“显式答案完成机制”或“独立重新采样”，但本轮不要把这些改变混入生成预算实验。
